# 面试讲法

## 1. 一句话介绍

我做了一个智能工单多 Agent 质量评测平台：产品上覆盖工单从提交到分派、回复、质检、关闭的闭环；技术上使用 4 个 Agent 和状态机实现编排；质量上使用 Benchmark、规则断言、Trace 和缺陷归因做可回归评测。

## 2. 为什么这个项目适合测试开发

- 不是只测最终答案，而是测 Agent 中间链路
- 不只测功能，还测安全、成本、鲁棒性、幂等
- 不只写用例，还建设数据集、指标和缺陷归因体系
- 不只是本地 Demo，还具备 CLI、报告、CI 接入点

## 3. 常见追问

### 为什么用多 Agent

因为工单链路天然可拆分：理解、处理、回复、质检的输入输出不同，拆分后可以单模块评测，也能做端到端评测。

### 怎么防止 Agent 乱回复

质检 Agent 会检查风险标记、知识依据、路由结果和最终动作。高风险工单统一转人工，禁止自动回复。

### 怎么测状态机

通过显式 Transition 表限制合法流转，并用 pytest 覆盖合法路径、非法跳转、终态和重复事件。

### 怎么处理 LLM 随机性

默认使用规则 Provider 形成稳定基线；真实 LLM 通过 Provider 接口接入，并结合多次运行、Judge 和人工锚点评估稳定性。

### 怎么归因

Trace 会记录每一步输入、输出、耗时和错误。缺陷可以归到理解、检索、路由、回复、质检、状态或 Provider。

### 数据从哪里来

当前使用人工构造的 L1~L3 Benchmark。生产环境可以从历史工单、客服记录和线上 Bad Case 中采样，并做脱敏与人工标注。

## 4. 可以量化的指标

- 单 Agent Schema 合规率
- 分类准确率
- 路由正确率
- 转人工准确率
- 状态流转合法率
- Benchmark 用例通过率
- 断言通过率
- Token/成本
- 平均延迟
- 高风险拦截率

简历中的业务数字必须来自真实运行记录，不要编造。
